## 重要约束：job 级 if 不能用 matrix（已踩坑）
- GitHub Actions 的 `jobs.<job_id>.if` **不支持 `matrix` 上下文**（报错：Unrecognized named-value: 'matrix'）；`matrix` 只在 **step 级 `if`** 可用。job 级 `if` 可用：github / needs / vars / inputs。
- 正确做法：想让"部分 matrix 变体仅手动"必须**拆成两个 job**，job 级 `if` 只用 `github.event_name == 'workflow_dispatch'`；不能用 job 级 if 按 matrix 值筛选。
- 已在 `build-cpu.yml` 拆为 `windows`（仅 x64-cpu-static，自动）与 `windows-extra`（openblas+arm64，job 级 if = workflow_dispatch，仅手动）。
- 注意：GitHub Actions **不支持 YAML 锚点**，拆分 job 时步骤需重复。
- 校验方法（可复用）：用 pyyaml 遍历所有 workflow 解析，并检测 `jobs.*.if` 里是否含 'matrix'（应恒为 0）。

## EL8 容器构建踩坑：ninja-build 不存在
- 报错 `No match for argument: ninja-build`：AlmaLinux 8 默认源+EPEL 里没有 `ninja-build`（它在 CRB/PowerTools 源）。
- 解决：**直接删掉这个包**——build-cpu.yml / server.yml 的 `cmake -B build` 没指定 `-G Ninja`，走默认 Unix Makefiles，根本不需要 ninja。（Windows job 的 `-G "Ninja Multi-Config"` 由 `choco install ninja` 提供，不影响。）
- 已确认 EL8 容器里其余包都能解析：git git-lfs wget which tar jq gcc-toolset-13 make cmake openssl-devel libjpeg-turbo-devel python3 python3-pip python3-devel glibc-langpack-en。
- ccache-action 会在容器内自行 `dnf install -y epel-release ccache`，所以后续步骤可直接用 EPEL 包（如 git-lfs/jq）。
- 观察点（下次运行若再失败）：`actions/setup-python@v6` 在 almalinux:8 容器里的兼容性（其 Python 构建可能要求比 EL8 glibc 2.28 更高）。备选方案：改用 `dnf install python3.11 python3.11-pip` + `ln -sf /usr/bin/python3.11 /usr/local/bin/python3`（/usr/local/bin 在 PATH 中优先于 /usr/bin，且不影响 dnf 的 /usr/bin/python3）。
- 注意：容器内 JS action（如 ccache-action）也是通过 docker exec 在容器里执行的，动作内的 dnf/命令都作用于容器。
